## 1. 安装

### 前置条件

1. **MuMu 模拟器 12**：官网 <https://mumu.163.com/> 下载安装，默认路径即可。
2. **MAA**：从 [官方 Release](https://github.com/MaaAssistantArknights/MaaAssistantArknights/releases) 下载 Windows 版压缩包，解压到任意目录。
   ⚠️ **务必先手动双击运行一次 MAA**，让它完成首次初始化（生成 `config`、`data` 等目录）。没初始化过的 MAA 无法被无人值守拉起。
3. **WebView2 运行时**：Win11 自带；Win10 若缺失，程序会自动降级为浏览器界面，不影响挂机功能。也可以[手动安装](https://go.microsoft.com/fwlink/p/?LinkId=2124703)以获得原生窗口体验。

### 用安装包安装

双击 `MAA挂机助手-安装包.exe`，向导会依次：

1. **检测环境**：报告是否找到 MAA 与 MuMu、WebView2 是否就绪；
2. **选择目录**：默认 `%LOCALAPPDATA%\MAA-Pipeline`（当前用户目录，不需要管理员权限）；
3. **附加选项**：是否创建桌面快捷方式、开始菜单项、装完是否立即启动；
4. 释放文件 → 创建快捷方式 → 写入卸载信息 → 完成。

两个版本的区别：

| 安装包 | 体积 | 适用场景 |
|---|---|---|
| `MAA挂机助手-安装包.exe` | 约 27 MB | 目标电脑已装 MAA，或想自己指定 MAA 位置 |
| `MAA挂机助手-安装包-完整版.exe` | 约 285 MB | 全新的电脑，装完即用（内置 MAA 本体与挂机配置） |

### 从源码运行（开发用）

```bash
python -m pip install pywebview pyinstaller pillow
python pipeline.py            # 启动界面
python pipeline.py --selftest # 只做环境自检
```

## 2. 首次配置

程序启动时会**自动探测** MuMu 与 MAA 的位置（扫描各盘符下的 `Program Files\Netease`、`MAA`、`Games` 等常见目录）。
探测成功会在日志里打印「路径自动探测 → …」。

如果日志出现「未能自动找到 …，请在界面『设置』里手动填路径」，就在右侧设置面板填写：

| 设置项 | 填什么 | 典型值 |
|---|---|---|
| 模拟器 CLI | `mumu-cli.exe` 的完整路径 | `C:\Program Files\Netease\MuMu\nx_main\mumu-cli.exe` |
| adb | 同目录下的 `adb.exe` | `C:\Program Files\Netease\MuMu\nx_main\adb.exe` |
| 实例序号 | 多开时第几个实例，从 0 开始 | `0`（第一个实例） |
| MAA 主程序 | `MAA.exe` 的完整路径 | `D:\MAA\MAA.exe` |

填写后点保存，再点一次界面上的「开始自检」确认三项都是 ✅。

> **多开实例与端口**：第 N 个实例（从 0 计）的 ADB 端口是 `16384 + 32 × N`。
> 例如实例 0 → `127.0.0.1:16384`，实例 1 → `127.0.0.1:16416`。程序会自动换算。

## 3. 界面说明

| 区域 | 内容 |
|---|---|
| **运行控制** | 模式选择（全流程 / 只开模拟器 / 只跑 MAA）、开始、中止；当前阶段进度条 |
| **运行记录** | 实时日志流（SSE 推送），含时间、级别、内容；可下载当天完整日志 |
| **设置面板** | 路径配置、定时设置、通知通道、托盘开关 |
| **底部** | 下次定时触发时间、当前状态、退出程序按钮 |

窗口行为：

- **点右上角关闭** = 最小化到托盘（挂机与定时继续在后台运行）
- **再次双击快捷方式** = 唤起已有窗口，不会启动第二个实例
- **托盘图标**：双击打开界面；右键菜单可打开界面 / 退出
- **真正退出**：托盘菜单「退出」，或界面里的「退出程序」按钮

## 4. 运行模式

| 模式 | 执行阶段 | 什么场景用 |
|---|---|---|
| **全流程** `full` | 启动模拟器 → 等就绪 → 校验 ADB → 跑 MAA → 收尾 | 日常一键挂机（默认） |
| **只开模拟器** `emu` | 启动模拟器 → 等就绪 → 校验 ADB | 模拟器已开着，只想把它拉起来 |
| **只跑 MAA** `maa` | 校验环境 → 跑 MAA → 收尾 | 模拟器已经在跑，只想补跑一次任务 |

任一阶段失败会**立即中断**，不会带着坏状态往下走。日志里会明确指出卡在哪一步。

### 任务完成后会自动做什么

MAA 跑完所有任务后，**它自己的窗口不会自动关闭**，所以收尾由本程序来做。判定依据是 MAA 核心日志里的
`任务已全部完成`，按下面的顺序执行：

1. 检测到「任务已全部完成」→ 在界面提示「N 秒后自动关闭 MAA 并收尾」；
2. 等满「关闭延迟」（默认 10 秒，给 MAA 一点时间落盘）后关闭 MAA：
   先给窗口发关闭消息让它正常退出，8 秒没反应才终止进程，再不行才强杀；
3. 关闭模拟器实例，并确认实例进程真的退出了（关闭指令是异步的，脚本会等它落地）；
4. 如果勾了「连同 MuMu 管理器窗口一起关闭」，再把 MuMu 管理器也关掉；
5. 还原 MAA 配置文件里的 `Current`，回到你原来的配置。

**保护机制**：如果全程没检测到「任务已全部完成」（例如你中途手动关掉了 MAA，或 MAA 报错退出），
模拟器会被**保留**不关，避免误杀你正在用的模拟器。

对应开关在设置面板里：模拟器区「任务完成后」的两个勾选项，以及 MAA 区的「完成后自动关闭 MAA」+「关闭延迟（秒）」。

## 5. 定时挂机

在设置面板的「定时」区域：

1. 打开「启用定时」；
2. 添加一个或多个时间点（如 `08:00`、`12:30`、`20:00`）；
3. 勾选生效的星期（默认全周）；
4. 建议保持「正在运行时跳过」开启，避免两次任务撞车。

触发判定用的是时间区间 `(上次检查, 现在]`，因此**电脑休眠期间跨过的时间点，唤醒后仍会补触发一次**（不会因为睡了 2 小时就整个漏掉）。

界面底部会显示「下次 08:00（今天，还有 50 分钟）· 每天 3 次 · 全周生效」这样的提示。

> 定时依赖程序常驻运行：**关窗口不等于退出**，缩到托盘后定时照常生效。

## 6. 通知渠道配置

挂机结束时（成功或失败）会向所有启用的渠道推送结果。每个渠道填写后都可以点旁边的「测试」按钮即时验证，
测试用的是**界面里当前填写的内容，不会写盘**，可以放心试错。

### 桌面气泡

默认开启，走系统托盘通知，不需要任何配置。若系统关闭了通知权限，可在「设置 → 系统 → 通知」里放行。

### 微信

| 渠道 | 获取方式 | 需要填 |
|---|---|---|
| **Server酱** | <https://sct.ftqq.com/> 微信扫码登录 → 复制 SendKey | `sendkey`（形如 `SCTxxxxxx`） |
| **PushPlus** | <https://www.pushplus.plus/> 微信登录 → 一对多推送 → 复制 token | `token`；群组推送可另填 `topic` |
| **WxPusher** | <https://wxpusher.zjiecode.com/> 创建应用 → 拿到 `app_token`，关注后拿 `UID` | `app_token` + `uids`（多个 UID 用逗号分隔） |

三者都是「关注公众号 → 推送到微信」的模式，任选其一即可；想更稳可以同时开两个。

### QQ

| 渠道 | 获取方式 | 需要填 |
|---|---|---|
| **Qmsg酱** | <https://qmsg.zendee.cn/> QQ 登录 → 添加机器人好友 → 复制 key | `key` + `qq`；群推送把 `type` 改为 `group` |
| **QQ 邮箱** | QQ 邮箱 → 设置 → 账户 → 开启 SMTP 服务 → 生成授权码 | 见下方「邮件」 |

### 邮件

填 SMTP 信息即可，QQ 邮箱示例：

| 字段 | 值 |
|---|---|
| SMTP 服务器 | `smtp.qq.com` |
| 端口 | `465` |
| 使用 SSL | ✅ |
| 用户名 | 你的 QQ 邮箱地址 |
| 密码 | **授权码**（不是 QQ 密码，在邮箱设置里生成） |
| 收件人 | 接收通知的邮箱，多个用逗号分隔 |

### 自定义 Webhook

填一个 URL，并选择报文格式，支持四种：

| 格式 | 报文结构 | 适用 |
|---|---|---|
| 通用 JSON | `{"title": "...", "content": "..."}` | 自建服务、n8n、IFTTT 等 |
| 企业微信 | `{"msgtype":"text","text":{"content":"..."}}` | 企业微信群机器人 |
| 钉钉 | `{"msgtype":"text","text":{"content":"..."}}` | 钉钉群机器人 |
| 飞书 | `{"msg_type":"text","content":{"text":"..."}}` | 飞书群机器人 |

## 7. 日志与排查

### 日志位置

| 文件 | 内容 |
|---|---|
| `logs\YYYY-MM-DD.log` | 本工具每天的运行记录（按天分文件，界面可下载） |
| `logs\startup.log` | 入口启动记录（含每次启动的 PID），用于区分「没启动起来」和「启动后崩了」 |
| `logs\startup-error.log` | 仅崩溃时生成，内含完整堆栈 |
| `MAA\debug\asst.log` | MAA 核心日志，挂机过程的问题看这个 |
| `MAA\debug\gui.log` | MAA 界面日志 |

### 常见问题

| 现象 | 原因与处理 |
|---|---|
| 启动后窗口一闪而过 | 看 `logs\startup-error.log`；多为缺 WebView2 或 Python 环境不完整 |
| 提示「找不到模拟器 CLI」 | 路径填错，或 MuMu 装在非默认位置 —— 在设置里手动指定 |
| 卡在「等待安卓就绪」 | 模拟器启动慢或损坏；把「等待超时」调大，或手动启动模拟器确认真能进桌面 |
| 卡在「确认 ADB 通路」 | 端口被占用或 adb 版本冲突；关掉其他模拟器/手机助手类软件后重试 |
| 「MAA 已在运行，请先关闭」 | 程序不会抢占已开着的 MAA，手动关掉再点开始 |
| 挂机没开始就结束了 | MAA 未初始化（先手动运行一次），或实例序号填错 |
| 挂机完成但模拟器没关 | 「关闭模拟器实例」没勾选，或 MAA 未报「任务已全部完成」（此时不关是保护机制） |
| 任务都跑完了，MAA 和模拟器却一直开着 | 升级到 v1.2.1 及以上。旧版监控循环只在 MAA 进程自己退出时才收尾，而 MAA 跑完并不会退出，会一直卡着 |
| MAA 关了但 MuMu 管理器窗口还开着 | 「连同 MuMu 管理器窗口一起关闭」默认开启；若你手动关掉了它，就不会再去关 |
| 定时不触发 | 程序是否还在运行（托盘里有图标）？时间点是否在今天勾选的星期内？ |
| 通知没收到 | 点「测试」按钮看返回信息，通常会直接告诉你凭据哪里不对 |

### 自检命令

```bash
python pipeline.py --selftest
```

会依次检查：依赖路径、MAA 配置文件与现有配置列表、模拟器状态、MAA 进程、托盘支持、界面文件、端口占用。
自检不启动界面，适合排查问题时快速定位。

## 8. 命令行参数

| 参数 | 作用 |
|---|---|
| （无） | 按配置打开界面（默认原生窗口） |
| `--selftest` | 只做环境自检，输出结果后退出 |
| `--window` | 强制使用原生窗口 |
| `--browser` | 强制使用浏览器界面 |
| `--no-tray` | 不创建托盘图标 |

配置项 `server.window_mode` 可取 `auto`（默认，有 pywebview 就用原生窗口）/ `window` / `browser`。

## 9. 卸载

- **安装包安装的**：控制面板 → 应用 → 找到「MAA 挂机助手」卸载；或直接运行安装目录下的 `uninstall.exe`。
  卸载会移除快捷方式、注册表项与安装目录（含日志与配置）。个别被占用的文件会在重启后自动清理。
- **绿色版 / 源码方式**：直接删除整个目录即可。
- **MAA 与 MuMu 本体不会被卸载**，需要的话请自行通过各自的卸载程序处理。
