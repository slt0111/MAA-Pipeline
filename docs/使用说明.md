## 1. 安装

### 前置条件

1. **MuMu 模拟器 12**：官网 <https://mumu.163.com/> 下载安装，默认路径即可。
2. **MAA**：从 [官方 Release](https://github.com/MaaAssistantArknights/MaaAssistantArknights/releases) 下载 Windows 版压缩包，解压到任意目录。
   ⚠️ **务必先手动双击运行一次 MAA**，让它完成首次初始化（生成 `config`、`data` 等目录）。没初始化过的 MAA 无法被无人值守拉起。
3. **WebView2 运行时**：Win11 自带；Win10 若缺失，程序会自动降级为浏览器界面，不影响挂机功能。也可以[手动安装](https://go.microsoft.com/fwlink/p/?LinkId=2124703)以获得原生窗口体验。

### 用安装包安装

双击 `MAA挂机助手-安装包.exe`，向导会依次：

1. **检测环境**：报告是否找到 MAA 与 MuMu、WebView2 是否就绪；
2. **选择目录**：默认 `%LOCALAPPDATA%\MAA-Pipeline`（当前用户目录，不需要管理员权限）；
3. **附加选项**：是否创建桌面快捷方式、开始菜单项、装完是否立即启动；
4. 释放文件 → 创建快捷方式 → 写入卸载信息 → 完成。

两个版本的区别：

| 安装包 | 体积 | 适用场景 |
|---|---|---|
| `MAA挂机助手-安装包.exe` | 约 27 MB | 目标电脑已装 MAA，或想自己指定 MAA 位置 |
| `MAA挂机助手-安装包-完整版.exe` | 约 285 MB | 全新的电脑，装完即用（内置 MAA 本体与挂机配置） |

### 从源码运行（开发用）

```bash
python -m pip install pywebview pyinstaller pillow
python pipeline.py            # 启动界面
python pipeline.py --selftest # 只做环境自检
```

## 1b. macOS 源码运行

Mac 以 **pywebview 原生窗口**为主（与 Windows 相同），浏览器只是 WebView 不可用时的回退。也可以自己打 `.dmg`（见 [1c](#1c-macos-打包-dmg)）。

1. **MuMu 模拟器（macOS）1.5.4+**：<https://mumu.163.com/mac/>  
   打开后到菜单「开发者 → 打开命令行工具」，确认能执行 `mumutool`。ADB 见「开发者 → 打开 ADB」。  
   开发者文档：<https://mumu.163.com/mac/tutorials/developer-document.html>
2. **MAA.app**（推荐，与 Windows 同一套注入 / 日志模型）：  
   从 [MAA Release](https://github.com/MaaAssistantArknights/MaaAssistantArknights/releases) 装 macOS 版，或 `brew install --cask maa`。  
   **先手动打开一次 MAA**，让它写出 `config/gui.new.json`（可能在 `.app` 旁或 `~/Library/Application Support/MAA`）。
3. **Python 3.10+** 与窗口 / 菜单栏依赖：

```bash
python3 -m pip install -r requirements-macos.txt
git clone <本仓库地址>
cd MAA-Pipeline
python3 pipeline.py --selftest
python3 pipeline.py
# 或：chmod +x start-pipeline.sh && ./start-pipeline.sh
```

`requirements-macos.txt` 含 `pywebview` 与 `pyobjc-framework-Cocoa`（菜单栏托盘）。没有 Cocoa 时关窗后进程仍在，二次启动会唤起，只是没有菜单栏图标。

首次运行会探测 `/Applications` 下的 `mumutool`、`MAA.app`，以及 Homebrew 的 `adb` / `maa`。找不到就在设置里填：

| 设置项 | 典型值 |
|---|---|
| 模拟器 CLI | `/Applications/MuMuPlayer.app/Contents/MacOS/mumutool`（实际以包内路径为准） |
| adb | `/opt/homebrew/bin/adb` 或 MuMu 自带 adb |
| ADB 地址 | **留空**（从 `mumutool info` 读端口），或填「打开 ADB」显示的 `127.0.0.1:端口` |
| MAA 主程序 | `/Applications/MAA.app`（或 Homebrew 的 `maa`） |
| maa-cli 配置目录 | 仅 maa-cli 需要；留空自动探测 |

**不要**把 Windows 的 `16384 + 32 × 索引` 套到 Mac 上。

### 备选：maa-cli

若只装了 `maa-cli`（`brew install MaaAssistantArknights/tap/maa-cli`），把「MAA 主程序」指到 `maa` 也能跑 `full` / 自检。行为：

- 不写 `gui.new.json`，启动命令为 `maa -p pipeline run pipeline_farm`；
- **多账号会切号**：每一号写入 `tasks/pipeline_farm.json` 里 StartUp 的 `account_name`（片段匹配规则与 GUI 相同），失败跳过仍有效；
- 连接写在 `profiles/pipeline.json`（`CompatMac` + 当前 ADB）；
- 日志走 maa-cli 的 stdout（不是 `debug/gui.log`）。

能装 MAA.app 时请优先用 GUI（日志与任务队列更接近 Windows）。

### 与 Windows 的对应关系

| 项目 | 状态 |
|---|---|
| 原生 pywebview 窗口 | 已对齐；无 WebView 才退回浏览器 |
| 关窗驻留 + 二次启动唤起 | 已对齐（Mac 在菜单栏） |
| 托盘菜单：显示 / 挂机 / 退出 | 已对齐；Mac 多一项「中止」 |
| 多账号切号（GUI） | 已对齐（`gui.new.json`） |
| 多账号切号（maa-cli） | 已支持（`pipeline_farm.json`） |
| 定时 / 远程通知 | 与 Windows 相同 |
| 桌面通知 | 走通知中心 |
| `.dmg` | 脚本已提供，须在 Mac 上打包；默认未签名 |
| 不附带 MuMu / MAA | 与 Windows 精简包相同 |

## 1c. macOS 打包 .dmg

必须在 **macOS** 本机执行（PyInstaller 不能在 Linux 交叉编出 Mach-O / `.app`）。仓库里的云端 Linux worker 只能跑 `--check` / `--dry-run`。

```bash
python3 -m pip install -r requirements-macos.txt pyinstaller
python3 build_dmg.py
# 或 ./scripts/build_dmg.sh
```

产物：

- `dist/MAA挂机助手.app`
- `dist/MAA挂机助手.dmg`（卷名「MAA挂机助手」，内含上述 `.app`）

**不含** MuMu、MAA.app、maa-cli。目标机器需自行安装。

签名与公证（可选后续）：

| 步骤 | 本仓库是否自动做 |
|---|---|
| `codesign --deep --options runtime` | 仅当设置了环境变量 `MAA_CODESIGN_ID` |
| `xcrun notarytool submit` / staple | **不做**，需 Apple 开发者账号时自行处理 |

未签名时 Gatekeeper 可能拦截：在 Finder 里右键「打开」，或到系统设置 → 隐私与安全性放行。

## 2. 首次配置

程序启动时会按**当前操作系统**自动探测 MuMu 与 MAA 的位置。
Windows 扫描各盘符下的 `Program Files\Netease`、`MAA`、`Games` 等；macOS 看 `/Applications` 里的 MuMu / MAA.app 以及 Homebrew。
探测成功会在日志里打印「路径自动探测 → …」。已有 `pipeline_config.json` 里的有效路径不会被默认值覆盖。

如果日志出现「未能自动找到 …，请在界面『设置』里手动填路径」，就在右侧设置面板填写：

| 设置项 | 填什么 | 典型值 |
|---|---|---|
| 模拟器 CLI | Windows：`mumu-cli.exe`；Mac：`mumutool` | `C:\Program Files\Netease\MuMu\nx_main\mumu-cli.exe` |
| adb | Windows：同目录 `adb.exe`；Mac：Homebrew 或模拟器自带 | `C:\Program Files\Netease\MuMu\nx_main\adb.exe` |
| 实例序号 | 多开时第几个实例，从 0 开始 | `0`（第一个实例） |
| ADB 地址 | 留空则自动推导 | Windows：`16384+32×N`；Mac：读 mumutool |
| MAA 主程序 | Windows：`MAA.exe`；Mac：`MAA.app` 或 `maa` | `D:\MAA\MAA.exe` |
| maa-cli 配置目录 | 仅主程序指向 `maa` 时需要，留空自动探测 | `~/Library/Application Support/com.loong.maa/config` |

填写后点保存。命令行 `python pipeline.py --selftest`（Mac 用 `python3`）可确认路径。

> **Windows 多开端口**：第 N 个实例（从 0 计）的 ADB 端口是 `16384 + 32 × N`。
> 例如实例 0 → `127.0.0.1:16384`，实例 1 → `127.0.0.1:16416`。
> **macOS 不要套用这个公式**，以 MuMu「打开 ADB」或 `mumutool info` 为准。

## 3. 界面说明

| 区域 | 内容 |
|---|---|
| **运行控制** | 模式选择（全流程 / 只开模拟器 / 只跑 MAA）、开始、中止；当前阶段进度条 |
| **运行记录** | 实时日志流（SSE 推送），含时间、级别、内容；可下载当天完整日志 |
| **设置面板** | 路径配置、多账号列表、定时设置、通知通道、托盘开关 |
| **底部** | 下次定时触发时间、当前状态、退出程序按钮 |

窗口行为：

- **点右上角关闭** = 不退出进程（Windows 缩到托盘；macOS 缩到菜单栏）
- **再次启动** = 唤起已有窗口，不会启动第二个实例
- **托盘 / 菜单栏**：显示主界面、立即挂机、退出（Mac 另有「中止」）
- **真正退出**：界面里的「退出程序」按钮，或托盘 / 菜单栏里的「退出」

## 4. 运行模式

| 模式 | 执行阶段 | 什么场景用 |
|---|---|---|
| **全流程** `full` | 启动模拟器 → 等就绪 → 校验 ADB → 跑 MAA → 收尾 | 日常一键挂机（默认） |
| **只开模拟器** `emu` | 启动模拟器 → 等就绪 → 校验 ADB | 模拟器已开着，只想把它拉起来 |
| **只跑 MAA** `maa` | 校验环境 → 跑 MAA → 收尾 | 模拟器已经在跑，只想补跑一次任务 |

任一阶段失败会**立即中断**，不会带着坏状态往下走。日志里会明确指出卡在哪一步。

### 任务完成后会自动做什么

MAA 跑完所有任务后，**它自己的窗口不会自动关闭**，所以收尾由本程序来做。判定依据是 MAA 核心日志里的
`任务已全部完成`，按下面的顺序执行：

1. 检测到「任务已全部完成」→ 在界面提示「N 秒后自动关闭 MAA 并收尾」；
2. 等满「关闭延迟」（默认 10 秒，给 MAA 一点时间落盘）后关闭 MAA：
   先请窗口自己退出（Windows 发 WM_CLOSE，Mac 用系统退出 / SIGTERM），8 秒没反应才终止进程，再不行才强杀；
3. 关闭模拟器实例，并确认实例进程真的退出了（关闭指令是异步的，脚本会等它落地）；
4. 如果勾了「连同 MuMu 管理器窗口一起关闭」，再把 MuMu 管理器也关掉；
5. 还原 MAA 配置文件里的 `Current`，回到你原来的配置。

**保护机制**：如果全程没检测到「任务已全部完成」（例如你中途手动关掉了 MAA，或 MAA 报错退出），
模拟器会被**保留**不关，避免误杀你正在用的模拟器。

对应开关在设置面板里：模拟器区「任务完成后」的两个勾选项，以及 MAA 区的「完成后自动关闭 MAA」+「关闭延迟（秒）」。

配置了多个账号时，模拟器只在**全部账号**都报「任务已全部完成」后才关；中途某一号失败则保留模拟器。

## 5. 多账号顺序挂机

同一台 MuMu 实例上按列表**一个接一个**挂，不是多开模拟器并行。

### 前提

1. 这些账号已经在该模拟器的客户端里登录过（官服 / B 服等）。本工具不会帮你输入密码。
2. MAA 任务队列里要有「开始唤醒」。切号只在这个任务执行时发生。
3. `account_name` 填登录名的**唯一片段**，规则与 [MAA 官方说明](https://docs.maa.plus/zh-cn/manual/introduction/startup.html) 相同：
   - 官服手机号 `123****4567`：可填 `4567`、`123`、`123****4567`
   - B 服昵称 `张三`：可填 `张三`、`张`、`三`（保证在已登录列表里唯一）

### 怎么配

在设置面板的「多账号」区域：

1. 点「添加账号」，填**显示名**（只给日志看）和 **MAA 匹配片段**；
2. 勾选要跑的号，用 ↑↓ 调顺序；
3. 保存后再点一键挂机。

列表为空或只留一个号时，行为和以前的单账号完全一样。

### 实际怎么跑

1. 模拟器只启动一次；
2. 对每个启用账号：按当前后端写入该号的 `account_name`（GUI：`gui.new.json`；maa-cli：`pipeline_farm.json`）→ 拉起 MAA → 等到「任务已全部完成」→ 关掉 MAA（cli 则自行退出）；
3. 再注入下一号的切号字段，重复；
4. 某一号没跑完（没看到「任务已全部完成」、连接失败等）会**记失败并继续下一号**，不会带着这一号的错误停掉整轮。全部号跑完后日志和通知会写「完成 N/M，失败：…」，有失败则整轮不算成功，模拟器保留。
5. 点「中止」仍会立刻停掉整轮，不会当成可跳过的单号失败。上一号的 MAA 关不掉、切不了下一号时，会短重试后整轮失败。

日志里会打出 `══ 账号 1/3「官服主号」，匹配「4567」══` 这类标记。

## 6. 定时挂机

在设置面板的「定时」区域：

1. 打开「启用定时」；
2. 添加一个或多个时间点（如 `08:00`、`12:30`、`20:00`）；
3. 勾选生效的星期（默认全周）；
4. 建议保持「正在运行时跳过」开启，避免两次任务撞车。

触发判定用的是时间区间 `(上次检查, 现在]`，因此**电脑休眠期间跨过的时间点，唤醒后仍会补触发一次**（不会因为睡了 2 小时就整个漏掉）。

界面底部会显示「下次 08:00（今天，还有 50 分钟）· 每天 3 次 · 全周生效」这样的提示。

> 定时依赖程序常驻运行：**关窗口不等于退出**，缩到托盘后定时照常生效。

## 7. 通知渠道配置

挂机结束时（成功或失败）会向所有启用的渠道推送结果。每个渠道填写后都可以点旁边的「测试」按钮即时验证，
测试用的是**界面里当前填写的内容，不会写盘**，可以放心试错。

### 桌面气泡

默认开启。Windows 走托盘气泡；macOS 走通知中心。不需要额外账号。若系统关闭了通知权限，请在系统设置里放行。

### 微信

| 渠道 | 获取方式 | 需要填 |
|---|---|---|
| **Server酱** | <https://sct.ftqq.com/> 微信扫码登录 → 复制 SendKey | `sendkey`（形如 `SCTxxxxxx`） |
| **PushPlus** | <https://www.pushplus.plus/> 微信登录 → 一对多推送 → 复制 token | `token`；群组推送可另填 `topic` |
| **WxPusher** | <https://wxpusher.zjiecode.com/> 创建应用 → 拿到 `app_token`，关注后拿 `UID` | `app_token` + `uids`（多个 UID 用逗号分隔） |

三者都是「关注公众号 → 推送到微信」的模式，任选其一即可；想更稳可以同时开两个。

### QQ

| 渠道 | 获取方式 | 需要填 |
|---|---|---|
| **Qmsg酱** | <https://qmsg.zendee.cn/> QQ 登录 → 添加机器人好友 → 复制 key | `key` + `qq`；群推送把 `type` 改为 `group` |
| **QQ 邮箱** | QQ 邮箱 → 设置 → 账户 → 开启 SMTP 服务 → 生成授权码 | 见下方「邮件」 |

### 邮件

填 SMTP 信息即可，QQ 邮箱示例：

| 字段 | 值 |
|---|---|
| SMTP 服务器 | `smtp.qq.com` |
| 端口 | `465` |
| 使用 SSL | ✅ |
| 用户名 | 你的 QQ 邮箱地址 |
| 密码 | **授权码**（不是 QQ 密码，在邮箱设置里生成） |
| 收件人 | 接收通知的邮箱，多个用逗号分隔 |

### 自定义 Webhook

填一个 URL，并选择报文格式，支持四种：

| 格式 | 报文结构 | 适用 |
|---|---|---|
| 通用 JSON | `{"title": "...", "content": "..."}` | 自建服务、n8n、IFTTT 等 |
| 企业微信 | `{"msgtype":"text","text":{"content":"..."}}` | 企业微信群机器人 |
| 钉钉 | `{"msgtype":"text","text":{"content":"..."}}` | 钉钉群机器人 |
| 飞书 | `{"msg_type":"text","content":{"text":"..."}}` | 飞书群机器人 |

## 8. 日志与排查

### 日志位置

| 文件 | 内容 |
|---|---|
| `logs\YYYY-MM-DD.log` | 本工具每天的运行记录（按天分文件，界面可下载） |
| `logs\startup.log` | 入口启动记录（含每次启动的 PID），用于区分「没启动起来」和「启动后崩了」 |
| `logs\startup-error.log` | 仅崩溃时生成，内含完整堆栈 |
| `MAA\debug\asst.log` | MAA 核心日志，挂机过程的问题看这个 |
| `MAA\debug\gui.log` | MAA 界面日志 |

### 常见问题

| 现象 | 原因与处理 |
|---|---|
| 启动后窗口一闪而过 | 看 `logs\startup-error.log`；多为缺 WebView2 或 Python 环境不完整 |
| 提示「找不到模拟器 CLI」 | 路径填错，或 MuMu 装在非默认位置 —— 在设置里手动指定 |
| 卡在「等待安卓就绪」 | 模拟器启动慢或损坏；把「等待超时」调大，或手动启动模拟器确认真能进桌面 |
| 卡在「确认 ADB 通路」 | 端口被占用或 adb 版本冲突；关掉其他模拟器/手机助手类软件后重试 |
| 「MAA 已在运行，请先关闭」 | 程序不会抢占已开着的 MAA，手动关掉再点开始 |
| 挂机没开始就结束了 | MAA 未初始化（先手动运行一次），或实例序号填错 |
| 多账号某一号失败后还在跑后面的号 | 这是刻意的：单号失败会跳过并继续。整轮结果看收尾摘要「完成 N/M，失败：…」 |
| 多账号中途整轮停住了 | 多半是点了「中止」，或上一号的 MAA 关不掉无法切号。后者会短重试后报错 |
| 切号没有发生 | 开始唤醒未启用、片段配错，或号还没在客户端登录过。maa-cli 路径请确认设置里主程序是 `maa`，且 `tasks/pipeline_farm.json` 里 StartUp 带了 `account_name` |
| 挂机完成但模拟器没关 | 「关闭模拟器实例」没勾选，或 MAA 未报「任务已全部完成」（此时不关是保护机制） |
| 任务都跑完了，MAA 和模拟器却一直开着 | 升级到 v1.2.1 及以上。旧版监控循环只在 MAA 进程自己退出时才收尾，而 MAA 跑完并不会退出，会一直卡着 |
| MAA 关了但 MuMu 管理器窗口还开着 | 「连同 MuMu 管理器窗口一起关闭」默认开启；若你手动关掉了它，就不会再去关 |
| 定时不触发 | 程序是否还在运行（托盘里有图标）？时间点是否在今天勾选的星期内？ |
| 通知没收到 | 点「测试」按钮看返回信息，通常会直接告诉你凭据哪里不对 |

### 自检命令

```bash
python pipeline.py --selftest
```

会依次检查：依赖路径、MAA 配置文件与现有配置列表、模拟器状态、MAA 进程、托盘支持、界面文件、端口占用。
自检不启动界面，适合排查问题时快速定位。

---

## 9. 命令行参数

| 参数 | 作用 |
|---|---|
| （无） | 按配置打开界面（默认原生窗口） |
| `--selftest` | 只做环境自检，输出结果后退出 |
| `--window` | 强制使用原生窗口 |
| `--browser` | 强制使用浏览器界面 |
| `--no-tray` | 不创建托盘图标 |

配置项 `server.window_mode` 可取 `auto`（默认，有 pywebview 就用原生窗口）/ `window` / `browser`。

## 10. 卸载

- **安装包安装的**：控制面板 → 应用 → 找到「MAA 挂机助手」卸载；或直接运行安装目录下的 `uninstall.exe`。
  卸载会移除快捷方式、注册表项与安装目录（含日志与配置）。个别被占用的文件会在重启后自动清理。
- **绿色版 / 源码方式**：直接删除整个目录即可。
- **MAA 与 MuMu 本体不会被卸载**，需要的话请自行通过各自的卸载程序处理。
